# 검색: 장소 이름으로 기준점 정하기

## 목적

사용자가 국내 장소 이름, 체크인·체크아웃, 인원을 한 번 입력하면 그 장소의 위치를 자동으로 찾아 [기준점](../../../GLOSSARY.md)으로 정하고 결과 화면으로 넘어간다. 위치를 따로 찾아보는 번거로움을 없애는 것이 이 작업의 핵심이다. 숙소, 음식점·카페, 날씨 결과는 이후 작업에서 이 기준점을 써서 채운다.

## 참고 자료

- [PRODUCT.md](../../../PRODUCT.md): 국내 전용, 입력은 한 번, 휴대폰에서 바로 쓸 수 있어야 한다는 앱 전체 전제를 따른다.
- [UI 구성 원칙](../../decisions/ui-composition.md): 검색 폼, 후보 선택, 빈 상태·오류 상태의 구성 원칙을 정한다.
- [프로토타입](prototype.html): 승인된 홈·검색 결과·숙소 상세·모바일 화면이다. 이 작업에서는 홈 검색바, 추천 목록, 후보 확인, 결과 화면 상단 요약과 조건 변경, 화면 배치와 반응형 동작을 정한다. 숙소·주변 정보·날씨 작업도 같은 파일을 따른다. 색 값과 홈 배경은 프로토타입이 아니라 아래 시각 정체성과 이 스펙의 계절 배경 기준을 따른다.
- [시각 정체성](../../decisions/visual-identity.md): 색 조합, 글꼴, 대비, 인터랙션 규칙을 정한다.

## 사용자에게 보이는 결과

- 홈에서 장소 이름, 체크인·체크아웃, 성인 수, 아동 수를 입력하고 검색할 수 있다.
- 장소 이름을 입력하는 동안 국내 장소 추천 목록이 나온다.
- 검색하면 결과 화면으로 넘어간다. 결과 화면 상단에 "○○(주소) 기준" 문구와 날짜·인원 요약이 보이고, 지도에 기준점이 표시된다.
- 결과 화면에서 검색 조건을 바로 고쳐 다시 검색할 수 있다.

## 범위

- 홈의 검색 입력과 국내 장소 추천 목록
- 추천을 고르지 않고 검색했을 때의 후보 확인 단계
- 기준점 확정과 결과 화면 이동
- 결과 화면 상단의 기준점·조건 요약과 조건 수정
- 결과 화면 지도의 기준점 표시
- 장소를 찾지 못했을 때와 입력이 잘못됐을 때의 안내

## 수용 기준

1. 장소 이름 칸에 글자를 입력하면 국내 장소만 추천 목록에 나온다.
2. 추천 목록에서 장소를 고르고 검색하면 확인 단계 없이 그 장소가 기준점인 결과 화면으로 넘어간다.
3. 추천을 고르지 않고 검색했을 때 국내 후보가 여러 곳이면 후보 목록과 함께 "어느 곳인가요?"를 묻는다. 사용자가 하나를 고르면 그 장소가 기준점이 된다.
4. 추천을 고르지 않고 검색했을 때 국내 후보가 딱 1곳이면 묻지 않고 그 장소가 기준점이 된다.
5. 국내에서 후보를 찾지 못하면 "찾지 못했어요"와 함께 다른 이름으로 다시 입력하라는 안내가 나오고, 입력한 내용은 그대로 남는다.
6. 인원은 성인 수와 아동 수만 입력한다. 기본값은 성인 2명, 아동 0명이고 성인은 1명 이상이어야 한다. 객실 수 입력은 없다.
7. 날짜를 고르지 않으면 체크인은 오늘, 체크아웃은 내일이 된다. 지난 날짜는 고를 수 없고, 체크아웃은 체크인보다 뒤여야 하며, 최대 30박까지 고를 수 있다. 조건에 맞지 않으면 검색 전에 이유를 보여준다.
8. 결과 화면 상단에 기준점 이름과 주소, 체크인·체크아웃, 인원이 보이고, 지도에 기준점 위치가 표시된다.
9. 결과 화면에서 조건을 고쳐 다시 검색하면 바뀐 조건과 기준점이 반영된다. 조건을 고칠 때도 1~5번 규칙이 똑같이 적용된다.
10. 결과 화면을 새로고침하거나 그 주소를 다른 사람에게 보내도 같은 기준점과 조건이 보인다.
11. 휴대폰 너비에서 입력, 후보 선택, 결과 화면 상단 요약을 모두 쓸 수 있다.
12. 홈 검색 영역의 배경은 한국 날짜 기준 계절(봄 3–5월, 여름 6–8월, 가을 9–11월, 겨울 12–2월)에 맞는 국내 자연 풍경 사진이다. 계절마다 사진 3장이 8초마다 부드럽게 바뀌고, 사진 위 점을 눌러 원하는 사진으로 바꿀 수 있다. 사진 위 글자와 검색바는 읽을 수 있어야 한다.
13. 움직임 줄이기 설정을 켠 사용자에게는 배경 사진이 저절로 바뀌거나 움직이지 않는다.
14. 배경 사진의 출처(사진가와 Unsplash)가 사진 위에 작게 보인다.
15. 장소 칸의 현재 위치 버튼을 누르면 브라우저 위치가 "현재 위치"라는 기준점으로 들어가고, 주소에는 그 근처 행정구역(예: 강원특별자치도 강릉시 교동)이 붙는다. 위치 권한이 없거나, 위치를 알 수 없거나, 국외이면 이유와 함께 장소 이름을 입력하라고 안내한다.

## 확정된 제약과 이유

- **국내 장소만 다룬다.** PRODUCT.md에서 해외 검색을 제외했다. 추천 목록과 후보 모두 국내로 제한한다.
- **추천을 고르지 않은 검색에서 후보가 여러 곳이면 한 번 묻는다.** 사용자가 직접 정했다. 단계가 하나 늘더라도 이름이 같은 다른 곳이 기준점이 되는 일을 막는 쪽을 택했다.
- **홈 배경은 계절 풍경 사진이 주기적으로 바뀐다.** 사용자가 직접 정했다. 사진은 Unsplash 라이선스(상업적 사용 무료, 출처 표기 의무 없음) 사진 12장을 2026-10-29에 사용자 승인을 받아 내려받아 앱에 포함했다.
- **인원은 성인·아동만 받고 객실 수는 받지 않는다.** 사용자가 직접 정했다. 2026-10-29 기준 SerpApi Google Hotels 문서에는 객실 수 항목이 없고 성인(`adults`)과 아동(`children`)만 있다. 국내 딥링크(야놀자)도 날짜와 인원을 URL에 담지 않는다. 그래서 객실 수를 받아도 가격에 반영할 수 없다. 객실 선택은 예약 사이트에서 한다.

## 가정 (바꿀 수 있음)

- 후보가 딱 1곳이면 묻지 않고 바로 진행한다. 이름이 같은 다른 곳이 잡힐 위험이 낮다고 판단했다.
- 아동 나이는 묻지 않는다. 입력 부담을 줄이려는 것이고, SerpApi에서도 선택 항목이다. 아동이 있을 때 가격이 실제와 다를 수 있다.
- 날짜 기본값은 오늘~내일 1박, 최대 30박이다. 30박이라는 상한은 숙소 데이터 쪽 한계를 확인하지 않고 정했다.
- 검색 조건은 결과 화면 주소에 담는다.
- 결과 화면의 지도는 이 작업에서 기준점 하나만 표시한다.
- 넓은 화면에서는 결과 화면을 목록 55%, 지도 45%로 나눈다. 태블릿 너비 이하에서는 목록이 기본이고 "지도 보기" 버튼으로 지도를 열며, 숙소 상세는 하단 시트로 연다(프로토타입).
- 제품 이름이 정해지지 않아 화면의 브랜드 표기는 "NOLJA"로 임시 표기한다.

## 범위 밖

- 숙소, 음식점·카페, 날씨 결과: 각 작업에서 다룬다. 이 작업의 결과 화면에서는 해당 영역이 아직 비어 있어도 된다.
- 선택한 숙소를 기준점으로 바꾸기: 주변 정보 작업에서 정한다.
- 해외 장소: PRODUCT.md에서 제외했다.
- 객실 수, 아동 나이 입력: 위 제약과 가정 참고.
- 최근 검색 기록, 즐겨찾기, 로그인: 요청받지 않았다.

## 미뤄 둔 것

- 검색 반경(처음 기획서의 기본 3km)과 사용자가 반경을 바꿀 수 있는지는 숙소·주변 정보 작업에서 정한다.

## 남은 위험

- 국내 추천 목록과 후보 검색은 Google Places API (New)의 Autocomplete(`includedRegionCodes`)와 Text Search를 쓸 예정이다. 추천을 고르면 좌표를 받으려고 Place Details를 한 번 더 부른다. 세션 토큰을 쓰지 않으면 요청마다 따로 과금된다고 문서에 나와 있다(2026-10-29 Code Assist 조회). 정확한 요청 필드는 구현 때 공식 문서로 다시 확인해야 한다.
- 현재 위치의 주소는 API 키에 Geocoding API가 없어서 Places Nearby Search로 가까운 5곳의 행정구역 이름을 모아 만든다(2026-10-31). 경계 근처에서는 동 이름이 이웃 동으로 잡힐 수 있다.
- 브라우저용 지도 키는 노출될 수밖에 없다. 도메인과 API 제한으로 보호해야 한다.
- 아동 나이를 받지 않아서, 아동이 있을 때 이후 숙소 가격이 실제와 다를 수 있다.
